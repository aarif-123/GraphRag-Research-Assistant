# API Endpoint Documentation

## Conventions and shared request models

The primary HTTP app is `app.main:app`. Its route contracts below are taken
from decorators and implementation; optional request-body fields use the
Pydantic models in `app/models/`. No global JWT guard exists. “Optional JWT”
means a valid bearer token may associate the request with a user; it is not
required unless stated.

Common research request fields (`ResearchRequest`):

| Field | Type/default | Validation |
|---|---|---|
| `query`, `text` | optional string | each max 2,000 chars; whitespace stripped; one must be supplied |
| `top_k` | int, 8 | 1–20; free plan clamps to configured free cap |
| `min_similarity` | float, 0.28 | 0–1 |
| `use_heavy` | bool, false | free plan disables it |
| `verify` | bool, true | verification runs only when evidence lists are non-empty |
| `filters` | optional object | graph filters consume `year` and `domain` |
| `temperature` | float, 0 | 0–2 |
| `mode` | optional string, `research` | `wikipedia` selects direct Wikipedia path |

`ConversationRequest` has a non-empty `messages` list of `{role, content}`,
the same retrieval/temperature controls, optional `last_paper_context`, and
`mode`. `BulkRequest` accepts 1–10 query strings and `top_k` 1–20.
`TimelineRequest`, `SurveyRequest`, `CompareRequest`, and the auth request
models are described on their endpoint rows.

## Main application endpoints

### Research and chat

| Method/path | Handler/source | Auth / rate limit | Request and execution |
|---|---|---|---|
| `POST /api/research` | `research()` → `_research_impl()` in `app/routes/research.py` | Optional JWT; explicit IP limit; request timeout | `ResearchRequest`. Handles PDF URL, uploaded PDF, wiki prefix/mode, direct planner routes, or full retrieval/generation. Returns answer, route/plan, papers/chunks, datasets/repos, verification, latency, model, warning, credits. Timeout → 504; LLM failure → 502; PDF parse failure → 400. No evidence → grounded refusal response (200). |
| `POST /api/research/timeline` | `research_timeline()` in `app/routes/research.py` | No JWT requirement; rate limit; credit call | `TimelineRequest`: topic ≤500 chars, optional year bounds, top_k 1–30, temperature 0–2. Fan-outs graph, vector, arXiv, CORE; generates with heavy model. Returns answer, papers/chunks/arXiv list and latency. Graph/vector errors are often reduced to empty results; embedding error → 502. |
| `POST /api/research/survey` | `research_survey()` | Pro required; rate limit | `SurveyRequest`: topic ≤500, top_k 5–30 (default 15), `use_heavy`, temperature. Parallel retrieval, optional graph co-citation, survey prompt and model call. Returns counts, papers/chunks/arXiv, answer and latency. Non-Pro → 403. |
| `POST /api/research/bulk` | `bulk_research()` | Pro required; rate limit | `BulkRequest`: 1–10 queries, top_k 1–20. Uses a semaphore capped at 3 and calls `_research_impl()` for each item; per-item exceptions become `{"query", "error"}` entries. Returns `{"results": [...]}`. |
| `POST /api/chat` | `chat_with_context()` → `_chat_impl()` in `app/routes/chat.py` | Optional JWT; explicit IP limit; request timeout | `ConversationRequest`. Extracts last user turn, handles wiki/context/entity/etc. routes, otherwise retrieves and synthesizes. Returns chat answer plus source and credit metadata. Timeout → 504; LLM failure → 502. |
| `POST /v1/chat/completions` | `chat_completions()` | Pro required; rate limit | `ChatCompletionRequest`: optional model, non-empty messages, temperature 0–2, max_tokens 1–4096, stream flag. `stream` is accepted but implementation returns a normal completion object. `model` selects heavy only for configured heavy ID or `"heavy"`; otherwise reason model. LLM error → 502. Usage token fields are `null`. |

### Graph endpoints in the main app

All paths below have prefix `/api/graph`. Data access is disabled/empty when
`FREEZE_RETRIEVAL=true`. Routes generally call the per-process IP limiter,
except `/trending`, which does not.

| Method/path | Handler | Auth | Request / response / behavior |
|---|---|---|---|
| `GET /api/graph/paper/{paper_id}` | `get_paper()` in `app/routes/graph.py` | No JWT; rate limit | Looks up full graph record by ID/title. Returns record; 404 if empty. |
| `GET /api/graph/author/{author_name}` | `get_author()` | No JWT; rate limit | Returns author papers/coauthors/venues; helper can return `{}` when frozen or unavailable. |
| `POST /api/graph/citation-path` | `citation_path()` | No JWT; rate limit | `CitationPathRequest {from_paper, to_paper}`. Returns `path_titles`, `path_length` (or helper error/fallback). |
| `GET /api/graph/trending?limit=10` | `trending()` | No JWT; no explicit route limiter | Integer `limit`; returns list, or `[]` when frozen/unavailable. No explicit range constraint in route. |
| `POST /api/graph/compare` | `compare_papers()` | No JWT required; rate limit; credit helper | `CompareRequest {paper_a, paper_b, aspects?, temperature}`. Graph lookup failure is treated as empty; embedding errors → 502; vector helper plus arXiv retrieval feed `compare_prompt`, then Groq. Returns query, answer, graph/arXiv papers, credit snapshot. |

### Authentication, profiles, and plan

All handlers are in `app/routes/auth.py`, with `/api/auth` prefix.

| Method/path | Handler | Auth | Request and behavior |
|---|---|---|---|
| `POST /api/auth/signup` | `auth_signup` | Public | `{email,password}`. Normalizes email; basic `@` check; password minimum 6; stores bcrypt hash and user document. Verification is bypassed by default; otherwise sends code and returns pending status. |
| `POST /api/auth/login` | `auth_login` | Public | `{email,password}`. Looks up user and verifies bcrypt hash; returns JWT, unless verification is required and user is unverified. Invalid credentials → 400. |
| `POST /api/auth/verify-email` | `verify_email` | Public | `{email,code}`. Checks stored code/expiry; marks verified, unsets token fields, returns JWT. |
| `GET /api/auth/verify-link?email=…&code=…` | `verify_email_link` | Public | Same stored-code validation; returns error HTML or redirects to `/?verified=true`. |
| `POST /api/auth/resend-verification` | `resend_verification` | Public | `{email}`; lookup and send link; user missing → 400. |
| `POST /api/auth/forgot-password` | `forgot_password` | Public | `{email}`; returns a generic response for unknown addresses; sends reset code for known user. |
| `POST /api/auth/reset-password` | `reset_password` | Public | `{email,token,new_password}`; validates stored token/expiry and min length 6, replaces hash. |
| `PUT /api/auth/profile` | `auth_update_profile` | Bearer JWT required | Optional `full_name`, `institution`, `role`; merges into `user_metadata`; returns user profile. |
| `PUT /api/auth/password` | `auth_update_password` | Bearer JWT required | `{password}`; min length 6; updates hash. Does not request current password in this schema. |
| `GET /api/auth/me` | `auth_me` | Bearer JWT required | Returns `{id,email,user_metadata}`. |
| `GET /api/auth/plan` | `get_plan` | Bearer JWT required | Returns plan, credit values, and feature gates; credit amounts are unlimited-style when credit flag is disabled. |
| `POST /api/auth/upgrade` | `stripe_webhook` | Webhook; signature checked only if secret configured | Reads raw JSON and `stripe-signature`; updates plan for checkout completed or subscription deleted events. Returns `{"received":true}`. Invalid JSON/signature → 400. |

### Payments, history, and credits

`router_payments` and `router_history` use `/api` prefix.

| Method/path | Handler | Auth | Request and behavior |
|---|---|---|---|
| `POST /api/razorpay/create-order` | `razorpay_create_order` | No JWT check in handler | JSON `{amount,currency?}`. Requires Razorpay server keys; creates captured order using SDK in a thread. Misconfiguration → 503; SDK failure → 500. |
| `POST /api/razorpay/verify` | `razorpay_verify_payment` | Bearer JWT required | `RazorpayVerifyRequest` with order ID, payment ID, signature. HMAC-SHA256 validation then user plan set to Pro; invalid signature → 400. |
| `GET /api/razorpay/payments` | `get_payment_history` | Bearer JWT required | Returns most recent 20 payment docs for authenticated user. |
| `GET /api/history` | `list_history` | Bearer JWT required | Returns sessions owned by user, sorted by `updated_at` descending. |
| `POST /api/history` | `create_history` | Bearer JWT required | JSON title/messages (body parsing is permissive and defaults to empty object); inserts UUID session. |
| `PUT /api/history/{session_id}` | `update_history` | Bearer JWT required | Updates provided title/messages and timestamp, scoped by user. Missing session → 404. |
| `DELETE /api/history` | `delete_all_history` | Bearer JWT required | Deletes all sessions for user. |
| `DELETE /api/history/{session_id}` | `delete_history` | Bearer JWT required | Deletes session scoped by user; absent → 404. |
| `GET /api/credits` | `get_credits` | No JWT required; anonymous free snapshot | Returns plan/credit snapshot and costs only if enforcement is enabled. |

### Media endpoints

Handlers are in `app/routes/media.py`. `set_user_context()` is called but does
not make authentication mandatory.

| Method/path | Handler | Request and behavior |
|---|---|---|
| `POST /api/upload/pdf` | `upload_pdf` | Multipart `file`; `.pdf` filename and byte size checked (default max 20 MiB). Extracts text using PyMuPDF in a thread, truncates stored text to configured internal limit, inserts into `uploaded_pdfs`, returns ID/URL/name/length/truncation. |
| `GET /api/pdf/{pdf_id}` | `get_pdf_text` | Reads by ID after stripping `.pdf`; returns text/name or 404. No ownership check is visible in the document schema. |
| `POST /api/audio/transcribe` | `transcribe_audio` | Multipart file, optional language (default `en`) and prompt; max 24 MiB by default; posts to Groq Whisper endpoint with configured key rotation. Returns `{text}`; known hallucinated filler is blanked. |
| `POST /api/voice/transcribe` | `transcribe_audio` | Alias for `/api/audio/transcribe`. |

### Health and static frontend routes

| Method/path | Handler | Behavior |
|---|---|---|
| `GET /api/health`, `GET /health` | `health()` | Liveness-style JSON with `pool._ready`, Neo4j flag, cache sizes and a static feature list. |
| `GET /api/ready` | `readiness()` | 200 when `_ready`; otherwise 503. `_ready` only reflects Groq client/key presence after pool initialization, not every dependency. |
| `GET /api/health/full` | `full_health()` | Checks MongoDB and Groq; checks/skips Supabase, Neo4j, embeddings according to freeze flag; returns 200 or 207. |
| `GET /api/stats` | `stats()` | Asserts readiness, then returns graph stats (empty while graph retrieval frozen). |
| `GET /api/models` | `list_models()` | Returns configured reason/heavy/planner model IDs. |
| `GET /api/config` | `get_config()` | Returns Supabase URL and public anon key only; omits key if it equals service-role key. |
| `GET /`, `GET /app`, `/app/*`, `/` static mount | `app.main` handlers/mounts | Serves landing page/app frontend files. Main root and `/app` handlers are registered before static mounts. |
| `GET /favicon.ico`, `GET /favicon.png`, `GET /styles.css` | Static helpers | Serves files when present; favicon returns 204 if missing. |

## Separate legacy graph API

[`knowledge_graph/api.py`](../../knowledge_graph/api.py) defines a second
FastAPI app, started separately with `python -m knowledge_graph.api` only if a
launcher is added (the file's `__main__` uses Uvicorn). It has:

| Method/path | Behavior |
|---|---|
| `POST /api/graph/seed` | Creates constraints and seeds five hard-coded sample papers |
| `POST /api/graph/search` | `GraphSearchRequest` (keywords, limit 1–50, optional domain/min_year); returns papers and narrative |
| `GET /api/graph/paper/{identifier}` | Full record or 404 |
| `GET /api/graph/author/{author_name}` | Author network or 404 |
| `POST /api/graph/citation-path` | Start/end paper and max depth 1–10 |
| `GET /api/graph/trending` | Limit 1–20 and min_year 1990+ |
| `POST /api/graph/co-citation` | Paper IDs and limit 1–20 |

The standalone API has no auth or rate-limit middleware in its source.

## Response/error caveats

- Exact response schemas differ by route; JSON examples are intentionally not
  fabricated where fields vary with provider results.
- Several connectors log and return empty results rather than raising. A
  returned empty `datasets` array is therefore possible even when dataset
  search was attempted.
- `Request` models validate basic shape, but history endpoints parse raw JSON
  bodies manually.
- Rate limiting is not consistently applied to every endpoint (notably
  health/static and main-app trending).
- The `stream` property on the OpenAI-compatible request is not used to stream.
